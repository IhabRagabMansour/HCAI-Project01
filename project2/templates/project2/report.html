Design choices for the Palmer Penguins explainability dashboard, addressing the project sheet's required written explanation.

1. Preprocessing

Rows with any missing value are dropped (dropna(), 333 of 344 rows remain). The data is split into train/test (80/20, stratified by species with random_state=42). Both model families use a scikit-learn ColumnTransformer pipeline: numeric features are median-imputed; categorical features (island, sex) are most-frequent-imputed and one-hot encoded. Numeric scaling differs by model: logistic regression standardizes numeric features (it requires it), while decision trees do not scale — this keeps the plotted tree thresholds in real units (e.g. flipper_length_mm ≤ 206.5). The preprocessor and estimator are stored together as one fitted pipeline, so every prediction (dashboard, counterfactuals, PDP, ALE) applies identical preprocessing.

2. Decision-tree regularization grid

Ten decision trees are trained with max_leaf_nodes ∈ {{ tree_grid }}. This spans the complexity axis from a 2-leaf stump to a fully grown tree. Complexity is Ω = get_n_leaves().

3. Logistic-regression regularization grid

Eight multinomial L1 logistic regressions are trained with C ∈ {{ logreg_grid }} (solver=saga, max_iter=5000). Recall C is the inverse regularization strength: small C = stronger regularization = sparser model.

4. Logistic-regression complexity measure

Ω = number of nonzero coefficients (those with |coef| > 1e-6, counted across all three classes). We chose this because L1 regularization induces sparsity, and the count of nonzero coefficients is the most human-readable notion of "how many features the model actually uses." It pairs naturally with the L1 penalty (versus the L1- or L2-norm alternatives, which are less directly interpretable as "model size").

5. How λ selects among trained models

The λ slider does not retrain anything; it selects, post-hoc, among the already-trained grid. For every trained model we compute a selection score and pick the minimizer at the current λ (range {{ lambda_min }}–{{ lambda_max }}, step {{ lambda_step }}). This single selected model drives all dashboard panels (model display, counterfactuals, PDP, ALE), guaranteeing consistency. Ties are broken toward the simpler model.

13. The selection formula

The project sheet defines the criterion as the maximizer of 

score = acc_test - lambda * Omega        # maximized

which we implement directly in services/selection.py (select_best returns the grid entry with the highest score). At λ=0 this picks the most accurate model; as λ grows, the complexity term dominates and progressively simpler models win. Ties are broken toward the simpler model.

(Equivalently, this is the same as minimizing (1 − acc_test) + λ·Ω — the two differ only by the additive constant 1, so they always select the same model.) Concretely on this data: λ=0 selects an 8-leaf tree at 97% accuracy; λ≥0.01 selects the 3-leaf tree at 94% — the 3-class floor. The 2-leaf stump is never selected because it cannot separate three species.

6–7. Counterfactual sampling & feature perturbation

Counterfactuals are generated by local random sampling around the chosen example, using the currently selected model: sample N candidates near x, predict each, keep those predicted as the target species, rank by distance, return the best k. Each feature type is perturbed appropriately:

  • Biometric decimals (bill_length_mm, bill_depth_mm, flipper_length_mm, body_mass_g): Gaussian noise z = x + N(0, α·std), clipped to the observed range.
  • Year (discrete): rounded small Gaussian, clipped to the observed year range, kept integer.
  • Categoricals (island, sex): kept with probability 0.8, otherwise resampled to another valid category. Never perturbed with Gaussian noise.

If no counterfactuals are found, the search widens (more candidates, larger numeric noise, higher categorical-switch probability) and retries.

8. MAD-weighted L1 distance

distance(x, z) = sum_j |x_j - z_j| / MAD_j      (over numeric features)
MAD_j = median_i |x_ij - median_i(x_ij)|,  floored at 1e-6

Dividing by each feature's MAD makes the distance scale-invariant (a 1 mm change in bill length and a 100 g change in body mass are weighted by how variable each feature naturally is). Counterfactuals are ranked by ascending distance; ties break toward fewer categorical changes.

9. Manual PDP

For the selected feature we build a grid over its observed range. For each grid value v, we set the feature to v for every row, call predict_proba, and average over all rows. This is the Monte-Carlo estimate of Ex_B[ f(v, x_B) ] — the expectation over the marginal distribution of the other features. We plot one curve per species. No library PDP function is used.

10. Manual ALE

The observed feature values are split into equal-population (quantile) bins. For each bin [lo, hi) we take only the rows whose value falls in that bin (the conditional distribution), predict at hi and at lo, and average the difference — the local effect of moving across the bin. These local effects are accumulated across bins (the integral) and then centered so the data-weighted mean is zero. One curve per species. No library ALE function is used. Three implementation details: half-open bins (no double-counted edges), data-weighted centering (zero mean over the data, not over bins), and empty bins carry the accumulator.

Why ALE over PDP? PDP averages over the marginal, so under correlated features it probes unrealistic combinations. ALE uses local differences within bins of the conditional distribution, avoiding that extrapolation.

11–12. Exact vs. finite-difference derivatives for ALE

Logistic regression has exact partial derivatives because the multinomial softmax is differentiable: 

∂ p_c / ∂ x_j = p_c * ( beta_cj - sum_r p_r * beta_rj )

(with a scaling factor for standardized features). A decision tree does not. It is piecewise-constant inside leaves: the prediction is flat within a leaf and jumps at split thresholds, so the derivative is zero almost everywhere and undefined at the thresholds. Therefore ALE for a tree must use discretization / finite differences. Our finite-difference ALE works for both model families, which is why we use it uniformly.

Every panel of the dashboard — the model display, counterfactuals, PDP, and ALE — is derived from one shared selection function, so changing the model class or λ updates all of them consistently.
